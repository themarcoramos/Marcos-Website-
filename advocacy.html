A youth-mentoring enrollment platform built to protect applicant data, enforce safety requirements, and automate follow-up.

BBBS Community Hub: Enrollment & Mentorship Platform

The Challenge

Big Brothers Big Sisters of the Greater Sacramento Area had no unified system for enrollment. Applicant tracking depended on manual spreadsheets, separate form builders, and disconnected communication tools. Staff copied data between systems by hand, applicants repeated the same information across forms, and tracking mandatory safety requirements took constant manual oversight.

What I Built

I designed and built a custom web platform (React, Node.js/TypeScript, PostgreSQL) using AI-assisted development and deployed it on Replit. It centralizes volunteer and guardian enrollment from first application through interview and match records.

  • Linked records: A relational schema connects Bigs (volunteer mentors), Littles (youth), and parents/guardians, so each match is tracked in one place.
  • Compliance tracking and gating: Staff verify each required step (orientation, Live Scan, National Training, Mandated Reporter), and the platform keeps community features locked until all of them are complete. Interview scheduling opens once the orientation and application are done. Applicants move through a horizontal progress stepper instead of an overwhelming dashboard.
  • Data protection: Role-based access control, plus PII masking on AI-assisted features so child and family identifiers are masked before processing. Designed with reference to the NIST AI Risk Management Framework.
  • Automated reminders: Scheduled SMS and email reminders (1,700+ sent since July 2026) keep applicants moving through the funnel.

The Impact

Before the platform, some applicants sat in a pending status for years waiting to be matched. Since launch, the quickest matches now happen in a little over a month. The platform gives staff one place to track every applicant's progress, builds required safety checks into the workflow, and automates routine applicant follow-up. Staff no longer send applicants links to each step separately or do that follow-up by hand, an 85% reduction in staff time on that work. It now holds 150+ volunteer and guardian accounts, with new enrollments daily, so staff time can go toward interviewing and supporting mentoring matches.

Simplified excerpt: compliance gating logic

An illustration of how gating works: applicants see only enrollment features until staff verify the required background and safety steps.

// TypeScript: compliance gating and feature access (simplified)

export function evaluatePortalAccess(applicant: ApplicantProfile): PortalAccessState {
  // 1. Check mandatory security and compliance milestones
  const isComplianceCleared =
    applicant.orientationVerified &&
    applicant.liveScanCleared &&
    applicant.mandatedReporterCertified &&
    applicant.nationalTrainingCompleted;

  // 2. Limit unverified applicants to enrollment features
  if (!isComplianceCleared) {
    return {
      status: "enrolling",
      unlockedFeatures: ["EnrollmentStepper", "RequirementsHub"],
      lockedFeatures: ["CommunityFeed", "TicketClaims", "ActivityIdeas"],
      // Interview booking requires orientation and application completion
      interviewBookingAllowed: applicant.orientationVerified && applicant.applicationSubmitted
    };
  }

  // 3. Grant full access once fully verified
  return {
    status: "active",
    unlockedFeatures: ["*"],
    interviewBookingAllowed: true
  };
}
